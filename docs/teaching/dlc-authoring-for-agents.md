# 带着孩子写一关 DLC：Agent 带练指南

这份文档写给 **agent**，不是给学生看的说明书。

YAML 字段、图规则、最小示例仍以 [dlc-spec.md](../dlc-spec.md) 为准。金标准对照 [`dlc/sushi/shuidiao-getou/hailao-shuidiao/`](../../dlc/sushi/shuidiao-getou/hailao-shuidiao/)。先想清楚教什么，再动手填文件。

孩子大约 10 到 12 岁。你的工作是带着他走完五步：信息搜集 → 剧情设计 → 读诗教学 → 课堂教学 → 分镜生图。每一步先落一份「中间产物」，最后才誊到 YAML。

---

## Agent 总规则

1. **一次只推进一个环节，环节内也逐步确认。** 孩子没交出该环节产物，不跳到写 YAML，也不跳到下一环节。具体到环节内部：选项设计一个环节一个环节确认，不要几章一起甩给用户拍板；诗词解析先确认重点词注释、定稿后再确认名家点评，不要注释与点评一起生成。
2. **先问教学目标。** 开口先问：「这一课孩子离开时，应该记住哪 2–3 件事？」没有这张备课卡，不谈情节和题目。
3. **不发明新字段。** 字词注释和签注都落在现有 `poem.yaml` 的 `translation` / `note`。不要建议 `glossary`、`annotation` 之类还不存在的键。
4. **剧情选择不进测评。** 玩家在故事里选了哪条正路，不能改变课堂对错。见金标准 `quiz.yaml` 里的 `gradingPrompt`。
5. **对话里不改游戏代码。** 孩子写完 YAML 后，对照 [dlc-spec.md](../dlc-spec.md) 编译：`npm run compile:dlc` → `npm test` → `npm run dev`。
6. **用孩子听得懂的话。** 追问要短、具体；指出问题时给一个改法，不要一次列出十条原则。
7. **有历史原话就尽量用原话。** 人物、典故、战役若有传世原句（如《三国志》《资治通鉴》中的记载），优先引用原话；引用时在**正确选项**里补一句出处和说明（哪部书、大致何事），让学生既答对也学得到。不要把原话改成大白话再塞进干扰项。

中间产物统一落在 `assets/<poetId>/<work-slug>/`，按环节逐份落盘，确认后再誊进 DLC 的 YAML：

| 环节 | 中间产物 | 干什么用 | 最终落到 |
| --- | --- | --- | --- |
| 信息搜集 | `01_teaching-card.md` 备课卡 | 教材定位＋教学目标＋字词＋背景 | 不直接转 YAML |
| 剧情设计 | `02_story-beats.md` 故事线与关卡 | 故事线大方向＋章节节点设计 | `content/story.yaml` |
| 读诗教学 | `03_poem-notes.md` 诗词解析 | 逐句翻译＋哪些句子写 `note` | `content/poem.yaml` |
| 课堂教学 | `04_quiz-design.md` 考题设计 | 每题检验哪条目标＋正解＋HINT＋评分/总评草稿 | `content/quiz.yaml` |
| 课堂教学·试评 | `06_answer-samples.md` 答卷样例 | 几份假想学生答案，拿来试评分/总评提示词 | 试评用，不转 YAML |
| 生图准备 | `05_storyboard.md` 分镜表 | 每个场景/角色的画面描述，供生成背景与立绘 | 生成图进 DLC `assets/` |
| 汇总兜底 | `manifest.yaml` | 诗人、作者、起始页 | 五步后填 |

## 三个 Checkpoint（每完成一段，就让孩子测试验收）

带练不是一路写到尾才看效果。每跨过一个里程碑，就停下来「生成 → 测试 → 让孩子验收」。

| Checkpoint | 卡在哪一步之后 | 必先完成 | 验收动作 |
| --- | --- | --- | --- |
| CP1 · 剧情可玩 | 备课 + 故事线 + 关卡 | 誊 `content/story.yaml` | 编译跑起，孩子当玩家点一遍：每个分岔都走得通、错路真的 game over、结尾自然进读词 |
| CP2 · MVP 完整体验 | 诗词 + quiz | `poem.yaml` + `quiz.yaml` 全写完 | 完整编译、测试、自己点一遍：剧情 → 读词 → 课堂题全链路验收 |
| CP3 · 用户体验升级 | 分镜 + 生图 | 按 `05_storyboard.md` 生成背景/立绘 | 回游戏看画面是否贴合氛围、有无盖字 |

> 每个 CP 都以「孩子玩到了、说得出哪里不对」为过；没通过就只改本段，不进下一 CP。

## 1. 信息搜集

目标：先做**教材与课标定位**，再据教研目标产出一张 **备课卡**。这张卡在对话里写清楚即可，先不要打开 YAML。

### 教材定位（第一步先做这个）

教学目标不是孩子凭印象编的，而是先查出来的。动手填备课卡之前，先弄清这首诗在**现行统编版教材**里教什么：

1. **教材坐标**：这首诗在哪个年级、哪个单元、哪一课？例如《赤壁》是统编版（部编版）八年级上册第六单元第 26 课《诗词五首》之四，单元人文主题是「人应该有怎样的品格与志趣」。
2. **课标依据**：抄下所依据的《义务教育语文课程标准》（现行 2022 年版）条目，例如第四学段诗歌要求——「诵读古代诗词，能借助注释和工具书理解基本内容；注重积累、感悟和运用，提高自己的欣赏品味」。
3. **教研目标**：从该课常见教研目标里找出落实到本诗的那几条（如：读出韵味积淀 / 赏析托物咏史、以小见大、反面落笔 / 体会借史抒怀之情），作为备课卡的源头。

定位完，才进入下面的备课卡三栏。

### 备课卡至少有三栏

**教学目标（2–3 条）**，写成小学生能记住的句子，并标上类型，同时**标注它出自哪条教研目标/课标**：

| 类型 | 问的是什么 | 水调歌头金标准 | 课标/教研来源 |
| --- | --- | --- | --- |
| 事实 | 何时何地写的 | 熙宁九年（1076）中秋，苏轼在密州 | 课标：诵读理解基本内容 / 教研：写作背景 |
| 对象 | 心里装着谁 | 思念弟弟苏辙，已七年未见 | 教研：对象与情感 |
| 主题 | 想告诉读者什么 | 人有离合、月有圆缺，此事古难全；但仍祝愿长久、共明月 | 教研：赏析思想感情 / 主题提炼 |

> 目标必须能溯源。教研里没有、又进不了故事或课堂的，先放到一边，不要硬编。

**重点字词**：只收三类，不要做成逐字词典。

- 今义易混：如「归去」像回家，不是简单的「离开」。
- 典故名物：如「琼楼玉宇」「婵娟」。
- 全篇眼：如「不胜寒」里的犹豫。

水调歌头够用的一组：归去、琼楼玉宇、不胜寒、婵娟。

**背景知识**：必须能解释「为什么今晚会写这首」。流水账传记不够。

水调歌头的因果链：王安石变法争论 → 苏轼外放 → 兄弟天各一方 → 密州中秋七年未见 → 把酒问月，写成《水调歌头》。

### 三个追问，卡住质量

孩子交来备课卡后，用这三个问题检查，缺哪条就只补哪条：

1. 「不讲诗人传记，只看字面，这首还读得懂吗？」——读不懂，就要补背景或字词。
2. 「这个词不注，下一句会不会卡住？」——不会卡住的词删掉，别堆。
3. 「这件事会不会写进后面的题目？」——既不进故事、也不进课堂的材料，先放到一边。

> 三条都要对照**教材定位那一步查到的教研目标**来卡，而不是凭孩子当下的感觉。目标是查到的，不是编的。备课卡里每条目标都要能找到出处。

通过后再进入剧情设计。

## 2. 剧情设计

剧情设计分两步走：先定「故事线」大方向，再落「情节与选择」的节点。玩家要 **变成诗人**，在读词之前先感到那份心情。

中间产物统一写到项目根目录 `assets/<poetId>/<work-slug>/`（如 `assets/dumu/chibi/`），一边带练一边留档，最后才誊进 DLC 的 `content/story.yaml`。本环节对应 `02_story-beats.md`。

### 四条设计红线（两步都要对照）

1. **诗以言志，先立背景**：故事先讲明白诗人当时的境遇。不懂身世背景，就读不懂诗里的「志」。只讲情节不讲处境，是把咏史诗读成了故事会。
2. **文史常识可扩，但不离志**：允许超出课本补充文史常识，但每一条都要服务于让孩子理解这份「志」，不是炫学。
3. **要戏剧性，允许 game over**：选项不能「一眼看出对错」。错误项必须是**真实有吸引力**的历史岔路，选了在历史上走不通、导致这首诗写不成（game over），而不是故意设陷阱或嘲讽。
4. **结尾自然过渡到写诗**：故事是这首诗的「前传」，必须在最后一章自然落到「诗人动笔写这首诗」，再进读词。（旁白/史实省略 `nextNodeId` 即代表故事结束、进入读诗。）

### 第一步 · 选故事线（大方向，2–3 句）

只定大方向，**不要章节、不要具体选择**。一句梗概要讲清三件事：玩家变成谁、经历什么、为什么这样会通向这首诗。

- 先问孩子：「这首诗你想让他变成谁、去经历什么？有没有自己的想法？」
  - **孩子有想法** → 精炼成一句，再补 2 个同量级备选，凑成 3 选 1。
  - **孩子没想法** → 直接给 3 个不同方向的 2–3 句故事线梗概。
- 每条梗概都要过上面的四条红线。
- 产物：`assets/<poetId>/<work-slug>/02_story-beats.md` 的「故事线」一节，记下这 2–3 句梗概（选中的 + 备选）。

### 第二步 · 设计情节与选择（确定故事线后）

先给孩子介绍四种节点（只有这四种，别发明新的）：

| 节点 | 作用 | 接线规则 |
| --- | --- | --- |
| `narration` 旁白 | 代入、推进情绪，走直线 | 可接旁白/史实/选择 |
| `fact` 史实 | 分岔前把史实讲清，走直线 | 不能直连 `gameOver` |
| `choice` 选择 | 正路汇合到 `convergesTo` | 选项 ≥2，上不封顶 |
| `gameOver` 结局 | 历史走不通 | 只能由选项进入 |

再逐章设计。**章数不锁 3，可多可少**；每章先定「要让玩家明白的一句话」，再逐节点填正路/错路/汇合句。

- 正路口诀：口味可以不同，汇合句必须把教学目标再说一遍。
- 错路要说明「这首诗不会在今晚写成」，再让玩家回到刚才选择；错路要写得真实可信、有吸引力，不能一眼被排除，也不要嘲讽。
- `fact` 放在分岔前面：孩子还没看清史实，就不要让他选边。

图规则（汇合、无环、`gameOver` 只能由选项进入）见 [dlc-spec.md](../dlc-spec.md)。带孩子先画简图：起点 → 史实 → 选择 → 正路汇合 / 错路重来 → 下一章 →（最后）写诗 → 读词。简图对了再写节点。

产物：`assets/<poetId>/<work-slug>/02_story-beats.md` 的「关卡设计」一节，记章数、每章一句话、每个选择的正路/错路、汇合句。确认后写 `story.yaml`。

> **Checkpoint 1（CP1 · 剧情可玩）**：`story.yaml` 落好后，先编译、跑起来，让孩子把自己当玩家点一遍——正路能不能走通、错路是不是真的 game over、结尾是不是自然进读词。剧情验收通过，才进读诗教学。
>
> **CP1 占位脚手架（不改代码，只填 YAML）**：这一步只交付 `story.yaml`；`poem.yaml` 与 `quiz.yaml` 用占位，保证编译通过、孩子能一路点完四种节点，不出现「空白读词」或「空问答直跳总结」的断层：
> - `poem.yaml`：`title` 写作品名，`lines` 放四句原文，每句 `translation` 写「〔待建设〕」，`note` 写「剧情验收阶段，诗词解析制作中」。
> - `quiz.yaml`：`gradingPrompt` / `summaryPrompt` 写明占位用途；`questions` 只放一道 `choice` 题，`prompt` 说明「这是走流程的占位题」，选项里含「选这个」，`correctOptionId` 指向「选这个」，`classmateOptionId` 指向另一项。
> 进 CP2 时把这两份占位整体替换成真内容即可。

## 3. 读诗教学

一行诗在 YAML 里只有 `original`、`translation`、可选的 `note`。不要建议新字段。

### 先用教材注释列清单

动手写翻译前，先把**教材要求注释的重点词**列一份给用户（从备课卡「重点字词」里取，对照教材原注释）：一词一句，写清注释内容。列完问一句：「这些重点词，要增加还是删掉哪一个？」学生增删定稿后，再按下面三条决定每词放进翻译还是签注。

### 字词注释放哪

- 今义已经能懂的词：翻译里轻轻带过即可。
- 卡住阅读的词：翻译里写明白，或在签注里点这一个词。
- 不要为每个字做词典。备课卡上没列入的词，默认不注。

金标准例子：`line_08` 的签注写「婵娟指月亮」，而不是另开一张字词表。

### 哪些句子要写签注

签注 `note` 回答的是：**这一句在做什么**，不是把翻译再写一遍。

值得写签注的句子通常是：

- 情感转折（想走又怕冷）
- 全篇眼（难全、祝福）
- 字面好懂、用意不好懂（把问题抛给月亮）

不必每句都注。水调歌头只注了四句：

| 行 | 它在做什么 | 金标准签注 |
| --- | --- | --- |
| `line_01` | 抛问 | 中秋夜，苏轼先把问题抛给月亮。 |
| `line_03` | 犹豫 | 「归去」像回家。苏轼把月亮当成另一个家园，却又犹豫。 |
| `line_07` | 把理说开 | 这是全词最宽广的一句：天下人都会分别，月亮也不会永远圆。 |
| `line_08` | 送祝福 | 婵娟指月亮。这是苏轼对弟弟苏辙，也是对所有离别之人的祝福。 |

中间几句有翻译就够了。

### 签注怎么写

- 一句、具体、10 到 12 岁能读完。
- 可以点一个字，但不要堆出处、版本、后人评价。
- **好**：「『归去』像回家。苏轼把月亮当成另一个家园，却又犹豫。」
- **坏**：把翻译重复一遍；或「此句用比兴，承上阕出世之想」。

签注内容还有两条「必做」：

1. **先覆盖教材要求的关键体会**：备课卡/教研目标里点明要体会的那一句（全篇眼、思想感情），签注必须把这句话说清，不许漏。
2. **再补 2–3 个历史名家的关键点评**：围绕全篇眼那几句，挑历代名家的一句成说（一句点评，不是整段考据），列给用户挑——由用户决定放哪条、放几条，agent 别自己拍板。

## 4. 课堂教学

先问：「备课卡里哪几条值得当堂检验？」再出题。不要从「默写下一句」开始。

### 什么值得测评

- 教学目标里写过的，并且故事或读词里出现过的。
- 每题尽量写 `contextRefs`，指向故事节点或诗句，避免超纲。
- 一课 2–4 题够了。金标准是 1 道选择 + 2 道填空。

| 题型 | 适合问什么 | 水调歌头 |
| --- | --- | --- |
| 选择 `choice` | 单一事实；干扰项必须是真实记混 | 熙宁九年在密州；杭州、黄州是常见记混 |
| 填空 `open` | 对象或主题，要学生用自己的话 | 思念谁、难全与祝福分别想说什么 |

题目怎么写：问「为什么 / 想告诉读者什么」。少问默写。`explanation` / `referenceAnswer` 用小学生能跟读的句子。

**不要考剧情选择。** 玩家先写信还是先回忆童年，都不改变「他在思念苏辙」。

### 何解的 HINT：混淆还是帮助？

两种都要有，而且必须能被老师点评。何解是课堂装置，不是彩蛋。学生要判断：这句话能不能信。

**帮助型**（填空 `classmateIsCorrect: true`）

- 示范一条完整思路，让还没想出来的学生有台阶。
- 不要把所有采分点说尽到「学生无事可做」。
- 金标准 `q_brother`：何解说出苏辙和七年未见，帮助学生开口，但学生仍要用自己的话回答「为什么」。

**混淆型**（填空 `classmateIsCorrect: false`，或选择题让何解选错项）

- 必须是 **真实常见误会**，不是为了好玩而胡说。
- 金标准 `q_theme`：把「古难全」听成「分开就分开吧」。
- 金标准 `q_year_place`：何解选「元丰二年在杭州」，这是苏轼生平里容易记混的一站。

禁止：编造诗人没做过的事当干扰；用嘲讽当 HINT；整课全是帮助或全是混淆。帮助让学生敢写，混淆让学生学会辨别。

老师真正上课时会同时分析何解和学生。HINT 写完后，在对话里用一句话自检：「如果学生照抄何解，老师还讲得出东西吗？」帮助型照抄应基本正确但仍可补全；混淆型照抄应被老师纠正。

### 这一步的产物

先落 `assets/<poetId>/<work-slug>/04_quiz-design.md`：每题在检验备课卡的哪一条、题干、正确理解、何解 HINT 是帮助还是混淆、常见误会。确认后再写 `quiz.yaml`。`gradingPrompt` / `summaryPrompt` 只补充「本课看什么」，不能改写老师身份。

## 5. 分镜表与生图

MVP 能玩了，最后做画面升级。写分镜表交给生图，落 `05_storyboard.md`——**别直接用文字生成功能去猜画面**。

逐条写清：这是哪一章哪一场景、需要什么画面（背景 / 立绘 / 道具）、构图与配色关键词、色调是否与 `DESIGN.md` 一致。每条或每个场景一行，要能据它直接生成图。

两条**必须写进图描述**的构图红线：

1. **不要把正确答案画出来**：画面只渲染场景氛围、人物动作与情绪，不能把「哪条路是对的」剧透——关键线索、机关、抉择结果一律不画进图，正误留给文字与选择。
2. **上满下空、渐变接框**：图片上部 3/4 铺满主体，最下方 1/4 留作渐变深色延伸，用来承接底部选择框/文字区；构图时别把关键信息画进最下 1/4，避免被选择框盖住。

产物：`assets/<poetId>/<work-slug>/05_storyboard.md`，确认后按表生成图，落到 DLC 包的 `assets/`（背景/立绘见 dlc-spec）。

> **Checkpoint 3（CP3 · 用户体验升级）**：图生成后回游戏看——画面是否贴合 `DESIGN.md` 氛围、有没有盖住文字、背景与立绘是否匹配章节。画面验收通过，整关才算交付。
